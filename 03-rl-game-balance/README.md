# 03 · 用强化学习智能体审计游戏平衡性

我做了一款卡牌爬塔小游戏,然后训练了一个 AI 让它自己去打。真正的目的不是"让 AI 会玩",而是想实验:**用智能体反复通关来暴露出我自己没发现的设计问题** 也就是训练一个智能体来进行自动测试，结果它确实做到了,而且只花了约 70 秒。

![Mini Whisper 游戏界面](./assets/cover_game_ui.png)

## 游戏和 AI

《Mini Whisper》是一款"末日废土 + 赛博克系"风格的卡牌游戏:10 层楼、6 种敌人、15 张卡、6 条核心规则。我用 sb3-contrib 的 MaskablePPO 训练了一个智能体,在单张免费的 Tesla T4 上跑了 **4.4 分钟**、30 万步就收敛了。1000 局确定性评估下来,它在 **95.1%** 的对局里能打到 Boss 层,**56.1%** 直接通关(seed 42 初版原权重,1000 局)——后来我用三个种子复现了同一配置,基线均值是 57.63%,种子极差 5.8pt;下文凡说"相对基线"一律以 57.63% 为准。平均奖励 49.5。作为一次非正式的量级校准,我本人手玩一局拿到 40.55(n=1,不构成人机对比结论)。

主要的核心结论是下面这张图。

![卡牌使用频率](./assets/key_card_usage.png)

我统计了 AI 一千局里每张卡打出的次数,分布极度倾斜:**两张卡吃掉了 76% 的出牌量,另外两张几乎从没被打出(不到 0.15%)。** 很显然在设计的时候卡牌非常不均衡，有些卡强到离谱,有些卡等于废牌,而这个结论是 AI 用行为投票投出来的，代替了人类手动测试的部分。

## 项目收获

一个智能体在几十万步里被逼着找最优解,会直接放大设计里的漏洞、ai诚实地无视了一些看起来很酷但其实没用的机制。这正是人工试玩最难做到的——人有惯性、有偏好、会照着设计者的意图玩。AI 不会。基于它的行为,我给出了两条初步的设计改动假设:

- **"离子护盾"疑似过强。** AI 自己发现了一个"护盾 → 拆解 → 格式化记忆 → 再上护盾"的循环,能把绝大部分伤害清零。第一反应是把它的费用从 1 提到 2。
- **有两张卡是"死卡"。** "黑色低语"和"无名之吻"合计只占 0.2% 的出牌。它们的设计是用理智换伤害,但 AI 判断在任何它能走到的局面下这笔交易都不划算,所以直接不用。它们不是难用,是被其他卡严格支配了。

同样的统计置信度,靠人工试玩要攒好几周。AI 的 1000 局评估只用了约 70 秒(6 份 1000 局评估实测 59.8–78.3 秒,见各 `eval_*.json` 的 `elapsed_sec`)。在游戏测试中，ai把"凭手感调平衡"变成了"拿数据说话"。

## 改动验证:我推翻了自己三次

上面两条只是假设。我把它们实装、重新训练、用同一套协议做对照评估——结果是连着三轮都在推翻自己。

![平衡性改动回归验证](./assets/balance_validation.png)

**第一轮:给离子护盾加费用,完全无效。** 费用从 1 提到 2 之后,它的出牌占比是 45.44%,相比基线的 45.35% 纹丝不动——AI 依然把它当最优解,只是每回合能做的事变少了。代价是通关率从 **56.1% 崩到 37.3%**,还多出一张新的死卡。没有修复倾斜,只把游戏变难了。

**第二轮:改起手牌组,指标好转,但归因是错的。** 当时我据此得出「根因在起手牌组构成」——把初始牌组从 5 匕首 + 5 护盾改成 6 类卡混合后,头部占比降到 45.6%、通关率升到 64.7%,两个指标都变好了。我把它写成了结论。

**这句话是错的,而我是在第三轮才发现的。**

真正让牌组趋于噪声的是战斗后的掉落逻辑:每层用 `rng.choice()` 随机塞 1 张卡进牌组,全程不看层数。改起手等于在掉落随机性**之前**先把牌塞进手里,掉落那套机制一行没动——它绕过了根因,不是修复了根因。更糟的是,初始牌组窄本来是有意的设计,爬塔类游戏的构筑乐趣就建立在「起手很窄、靠过程变宽」上,我为了压一个指标把自己原本正确的设计给拆了。

**第三轮:正面修掉落机制,四个版本没有一个降低集中度。** 这轮我做了 4 组 × 3 个随机种子(42 / 7 / 123)共 12 次独立训练,每个模型各 1000 局评估:

| 指标 | 基线 | 掉落按层分档 | 卡牌数值修正 | 两者叠加 |
|------|------|-------------|-------------|---------|
| 通关率 (种子 42 / 7 / 123) | 60.1% / 58.5% / 54.3% | 55.9% / 55.6% / 51.1% | **74.9% / 71.6% / 71.1%** | 67.2% / 68.4% / 64.6% |
| 头部两张卡占比 | 75.6% / 75.3% / 76.9% | 77.3% / 78.1% / 78.7% | 79.0% / 79.3% / 79.5% | **81.3% / 84.4% / 80.2%** |

**四个版本无一降低集中度。** 这一轮里通关率越高的版本确实越集中(12 次运行 r=+0.52),但把 v1 / v2 两个历史锚点放进同一张散点图,相关性就消失了(15 点 r=0.03)。所以这不是规律——集中度与难度是两个可以各自移动的维度,而 v3 这三组只推动了难度,一次都没碰到集中度。我按「这张卡是否需要成型牌组才敢要」排的分档顺序,不但没降集中度,还把格式化记忆、亵渎协议、拆解三张卡从 2–3% 打到近 0%(三种子均值:拆解从 1.87% 掉到 0.21%,最极端的 seed 7 上是 2.31% → 0.03%)。原因很简单:7 层才放开、每层只掉 1 张、到 Boss 最多进 4 张,而牌组已经 16 张以上——**这些卡不是「晚点才强」,是「晚点等于没有」。**

最反直觉的一条来自数值修正组:**我把两张废卡的伤害提高了 44% 和 87%,它们的使用率反而掉了下去——三种子均值上,404·死灵协议 2.34% → 0.40%,亵渎协议 1.73% → 0.12%,到 v3ab 里亵渎才真的归零(均值 0.02%)。** 加强让局变短(平均决策步数 85.5 → 75.8),局变短意味着抽卡次数更少,非核心卡的出场机会被进一步挤掉。这说明它们不被使用的原因根本不是数值弱,**而是牌位、能量和抽卡机会——瓶颈发生在打出来之前,数值在这里不是可用的杠杆。**

## 修正后的结论

三轮下来,根因比我以为的更靠前一层。

四个版本都在动同一类东西:**掉落池里有哪些卡**。没有一个动了**掉落是怎么发生的**。`rng.choice(loot_pool)` 是「随机塞给你 1 张」,智能体对自己的牌组构成没有任何决策权——不能选、不能拒、不能规划。**既然构筑不是一个决策,牌组就必然趋向噪声,而对噪声牌组的最优策略只能是退回初始那两张稳定牌。** 只改池子范围而不改这一点,集中度当然不动;第三轮的失败恰好把这件事证明了,因为它是「范围假设」最认真的一次实现。

真正的修法是照《杀戮尖塔》做 **3 选 1**,让构筑重新成为一个决策。这需要改动作空间与观测空间、重写动作掩码并重训,尚未实现。

除了「构筑不是决策」这一层,第三轮还顺手把另外三层根因量了出来,它们各自对应不同的修法:

1. **机制刚需。** `env._start_turn()` 里有一行 `self.player["armor"] = 0`——护甲每回合清零,而打出去的伤害是留存的,所以护盾天然就是多余能量的默认去处。数据也对得上:同样每局被抽到约 50 次,护盾的抽到即打率比匕首高 11–15pt,四个版本无一例外。
2. **获取曲线。** 掉落是 `rng.choice()` 全池随机、不看层数,13 张非起手卡的供给被压成一条平线。
3. **费用失衡。** 3 能量 / 回合的粒度下,一张 2 费卡必须明显强过两张 1 费卡才有位置。

三层各自要用不同的修法,而数值层碰不到第一层。

四条方法论收获,对我来说比任何一个数字都重要:

1. **能改善指标的干预,不等于归因正确。** 对照实验能证伪一个假设,却不能证明一个成功干预的解释是对的——这两件事我在第二轮混为一谈了。
2. **必须先量出噪声底线,再谈效应。** 三种子跑下来,基线自身的通关率极差就有 5.8 个百分点。第二轮那个 +8.6pt 只比这条噪声底线高一点,单种子跑一次根本撑不起「找到根因」这种强度的结论。
3. **指标全绿和设计变差可以同时发生。** 第二轮两个指标双双改善,代价是构筑深度被抽掉;数值修正组通关率 +15pt,代价是集中度反升、两张卡彻底消失。这些代价在集中度和通关率上都看不见。
4. **数值层和机制层要分清。** 一张卡不被使用,可能是它弱,也可能是它根本没机会上场。前者调数值有用,后者调数值只会让情况更糟。

最后一条也界定了这套方法的边界:**智能体优化的是通关,不是乐趣。用 RL 做平衡审计,擅长的是暴露「哪些设计意图没有实现」,它不能替人回答「这个设计值不值得存在」。**

完整实验设计、数据与复现步骤见 [`experiments/`](./experiments)(第一、二轮)与 [`experiments-v3/`](./experiments-v3)(第三轮 4 组 × 3 个随机种子(42 / 7 / 123)共 12 次独立训练)。

## 技术实现

- **环境**:自己用 Gymnasium 写的卡牌环境。51 维观测、16 路离散动作,带非法动作掩码(所以用的是 MaskablePPO 而不是原版 PPO)。奖励函数是手工设计的稠密奖励,特意加了理智损失惩罚,防止 AI 学出"自杀式高伤"的畸形打法。
- **算法**:MaskablePPO + 2 层 MLP [128, 128],4 个并行环境,30 万步。单卡 T4,约 1100 env-steps/s,4.4 分钟收敛(这是 GPU 上的数字;`experiments/` 里那个「8 线程 CPU 约 4.2 分钟」说的是另一套硬件)。
- **收敛诊断**:approx_kl、clip_fraction、entropy_loss 三项指标都健康,从探索到利用的过渡很平滑,没有出现策略过早坍缩。
- **评估**:1000 局用的种子是 20000–20999,训练时完全没见过,避免数据泄漏。奖励分布是明显的双峰,精确对应"打到 Boss 但输了"和"通关"两种结局。

代码里带了四个打印式自检脚本(`test_env.py`、`test_cards.py`、`test_enemies.py`、`test_rules.py`),各跑一遍打印 ✅/❌ 计数,用来快速确认环境、卡牌、敌人、规则四块没写崩。它们不是 pytest 单元测试,也不构成规则的逐条形式化验证——规则层的硬伤是我自己试玩发现的,智能体负责的是只有大样本才显形的问题。

**关于人和智能体的分工,说清楚一点:** 这个项目里我的角色是人工试玩者 + 判断者。规则漏洞、明显过强的卡、循环断裂这类基础硬伤,我自己试玩几局就能发现,不需要智能体;智能体真正不可替代的地方是**只有在大样本下才会显形的问题**——出牌集中度、某个数值改动对通关率的真实影响、以及上面那种「加强一张卡反而让它消失」的反直觉效应。这两件事的分工不能互换,也不该互相包装。
