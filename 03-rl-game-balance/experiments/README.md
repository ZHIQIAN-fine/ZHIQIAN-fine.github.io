# 平衡性改动回归验证（v2 补充实验）

> ⚠️ **这一轮的结论后来被我自己推翻了。** 下文得出的「真正的根因在起手牌组结构」是错的：改起手其实是**绕过**了掉落随机性,而不是修复它,而且单种子跑一次的效应量不足以支撑这个强度的结论。完整的推翻过程、双种子数据和修正后的根因见 [`../experiments-v3/`](../experiments-v3)。本文保留原样,不做事后修饰。

初版分析止步于「发现失衡 + 提出改动建议」，建议本身没有被验证过。这组实验补上了闭环：把两条改动分别实装、重新训练、用同一套评估协议做对照，看改动到底有没有修复失衡、以及有没有伤到难度曲线。

**结论先行：初版提出的「给强势卡加费用」是错的。** 出牌集中度纹丝不动，通关率反而崩了 19 个百分点。真正的根因不在单卡数值，而在起手牌组结构。

![平衡性改动回归验证](../assets/balance_validation.png)

## 实验设计

三组共享同一套训练与评估协议，单一变量对照：

| 组别 | 改动内容 | 模型 |
|------|----------|------|
| v0 基线 | 无（原始版本） | [`../model/final_model.zip`](../model/final_model.zip) |
| v1 护盾提费 | 离子护盾 cost 1 → 2；疯狂卡理智消耗 3 → 1 | [`models/model_v1_cost_up.zip`](models/model_v1_cost_up.zip) |
| v2 起手多样化 | 初始牌组由「5 匕首 + 5 护盾」改为「3 匕首 + 3 护盾 + 触发链 / 冥想程序 / 进程冻结 / 代码污染 各 1」，**费用一律不动** | [`models/model_v2_deck_mix.zip`](models/model_v2_deck_mix.zip) |

训练：MaskablePPO，30 万步，4 并行环境，seed=42，超参与初版完全一致。
评估：1000 局确定性评估，种子 20000–20999（训练时未见过）。
v0 用原权重复现，结果与初版 `results/summary.json` 完全一致（76.45% / 56.1% / 49.47），确认基线可比。

## 结果

| 指标 | v0 基线 | v1 护盾提费 | v2 起手多样化 |
|------|---------|-------------|---------------|
| 头部两张卡出牌占比 | 76.45% | **77.15%**（未改善） | **45.60%** |
| 离子护盾单卡占比 | 45.35% | 45.44% | 25.47% |
| 通关率 | 56.10% | **37.30%** | **64.70%** |
| 抵达 Boss 层 | 95.10% | 89.40% | 97.50% |
| 平均奖励 | 49.47 | 41.37 | 52.20 |
| 出牌占比 < 0.5% 的卡 | 2 张 | 3 张 | 2 张 |

### v1：改动无效，且有副作用

把离子护盾的费用从 1 提到 2 之后，它的出牌占比是 45.44%——相比基线的 45.35% 没有任何变化。智能体依然把它当作最优解，只是每回合能做的事更少了，于是通关率从 56.1% 掉到 37.3%，404·死灵协议还多变成了一张新的死卡。

**这是数值调整里最差的一类结果：没有修复倾斜，只是把游戏整体变难了。**

### v2：根因在牌组结构

v1 的反常现象反推出一个假设——出牌集中也许不是因为这两张卡强，而是因为**起手牌组就是 5 张匕首 + 5 张护盾，玩家手里根本没有别的牌可打**。这是结构问题，不是数值问题。

只调整初始牌组构成、不动任何费用与数值后：头部占比从 76.45% 降到 45.60%，触发链、进程冻结、冥想程序、代码污染四张原本 1–3% 的卡回到 8–11% 的健康区间，**且通关率不降反升（56.1% → 64.7%）**，难度曲线没有被破坏。

### 修正后的结论

卡牌使用倾斜的主因是起手牌组构成，而非单卡强度。直接对强势卡加费用无法纠偏，还会同时推高难度。评估平衡性改动时必须同时盯两个指标——**出牌分布（是否修复倾斜）与通关率（是否破坏难度曲线）**，只看前者会误判，v1 就是典型。

两张疯狂卡（黑色低语、无名之吻）在三组里始终低于 0.15%，说明它们的问题独立于牌组结构，与触发条件（仅在理智 ≤ 10 时可获得）相关，需要单独处理。

## 复现

```bash
pip install -r ../requirements.txt

# 基线（1000 局评估，约 1 分钟）
python3 scripts/eval_balance.py ../code ../model/final_model.zip results/eval_v0_baseline.json 1000

# 复现某一实验组：先把对应 patch 打到 code/ 的副本上，再训练与评估
cp -r ../code /tmp/exp && (cd /tmp/exp && patch -p3 < <绝对路径>/patches/v2_deck_mix.diff)
OMP_NUM_THREADS=8 python3 scripts/train_cpu.py /tmp/exp /tmp/model_v2 300000
python3 scripts/eval_balance.py /tmp/exp /tmp/model_v2.zip results/eval_v2_deck_mix.json 1000

# 生成对比图
python3 scripts/make_chart.py
```

单张 CPU（8 线程）下训练约 4.2 分钟、1000 局评估约 70 秒，无需 GPU。

## 目录

| 路径 | 说明 |
|------|------|
| `patches/` | 两组改动相对原始 `code/cards.py` 的 diff |
| `models/` | 两组改动重新训练后的权重 |
| `results/` | 三组各 1000 局评估的完整结果（含逐卡出牌分布） |
| `scripts/` | 训练、评估、绘图脚本（CPU 可跑，路径全部参数化） |
