面向 **AI 产品经理**岗位。这里的项目都来自我的研究生课程,但我重新用产品视角组织了它们:每个项目都在回答"要解决谁的什么问题、我做了什么取舍、这个 AI 方案到底值不值得做"。

比起模型精度,我更在意能不能把技术能力翻译成清晰的产品判断。下面每个项目都配了一页说明,非技术读者只看"这是什么、有什么用、我学到了什么"就够了,技术读者可以往下深入到源码和报告。

## 为什么是这四个

我没有把所有课程作业都塞进来。作品集的目的是展示判断力,不是罗列工作量。这四个项目各自代表了 AI PM 需要的一种能力:

- **01 · 定义并落地一个 AI 产品。** 从模糊需求做到可用的 Agent,涉及提示工程、检索、人机协作、安全护栏。
- **02 · 判断一项 AI 技术该不该上线。** 我的结论是"现在只适合原型,不适合成品"。这种克制比盲目乐观更接近真实的产品决策。
- **03 · 从 AI 的行为里挖产品洞察。** 把模型当成分析工具,而不是终点。AI 打了 1000 局,替我找出了两处人工试玩几周都难发现的失衡。
- **04 · 敢于交付一个不好看的结论。** 模型只能解释 15.5% 的口碑波动,但"口碑无法靠价格和元数据预测"这件事本身,就是有价值的发现。我不会为了指标好看而粉饰它。

四个项目里,03 和 04 有可复现的完整代码和数据,01 有 Agent 实现代码,02 有完整的训练配置与实验报告。
